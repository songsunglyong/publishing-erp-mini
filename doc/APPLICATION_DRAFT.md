# Spring·JSP 신입 지원용 초안

작성 기준: 2026-10-21. 사용자가 제공한 사실은 PHP·Android·iOS 앱 유지보수 경험과 Spring/JSP/MySQL 신입 지원 희망이다. 경력 기간·회사·담당 기능·성과 수치는 아직 받지 않았으므로 만들지 않았다. 특정 채용 공고에 맞춘 최종 지원서가 아닌 공통 초안이다. 대괄호 항목은 실제 경험을 확인해 채운다.

## 이력서 제목

PHP·모바일 앱 유지보수 경험을 바탕으로 Java/Spring 웹 개발에 도전하는 지원자

## 소개

PHP 웹과 Android·iOS 앱 유지보수 경험이 있으며, Java/Spring 기반 웹 개발 직무로 역량을 넓히고자 합니다. 기존 업무 경험과 연결해 학습하기 위해 도서·거래처·주문·재고를 관리하는 출판 ERP 포트폴리오를 진행했습니다. Spring MVC의 요청 처리 흐름, MyBatis SQL, JSP 화면, 트랜잭션과 세션 보안을 중심으로 학습하고 있습니다.

## 프로젝트 요약 — 출판 ERP Mini

- 유형: 개인 학습·포트폴리오, 합성 데이터만 사용.
- 기술: Java 21, Spring Boot 4.1, Spring Security 7.1, MyBatis XML, JSP/JSTL, jQuery, MariaDB 11.4, Maven, JUnit 5/MockMvc.
- 기능: 도서·거래처 관리, 다품목 주문, 출고·취소·부분 반품, 재고 잔액·원장, 매출 보고서, 세션 기반 로그인과 역할 권한.
- 핵심 설계: 주문 당시 단가 보존, 서버 총액 계산, 출고 시 재고 잠금, 주문·재고·원장의 동일 트랜잭션, 중복 요청 방지.
- 검증: 실제 MariaDB·JSP HTTP·보안 검증을 포함한 현재 자동 테스트 93개 통과. 이전 92개 구성도 별도 소스 사본과 빈 테스트 DB에서 검증. 실제 브라우저 시연과 실행 WAR 동작 확인.
- 유지보수 사례: 임시 사본에 품목별 별도 커밋 버그를 심어 부분 재고 차감 재현 → 회귀 테스트 실패 → 트랜잭션 참여 방식 수정 후 통과.
- 저장소: https://github.com/songsunglyong/publishing-erp-mini — 현재 비공개. 심사자가 접근할 수 있도록 별도 열람 방법을 정해야 한다.
- 시연 URL: 아직 없음. 서버를 개설·배포하고 외부에서 검증한 뒤 기재한다.
- DB 표기: 이 프로젝트는 MariaDB다. MySQL 실무 경험이나 MySQL 배포 검증을 했다고 기재하지 않는다.

## 지원 동기·학습 과정 초안

PHP와 모바일 앱을 유지보수한 경험을 바탕으로 Java/Spring 웹 개발 직무에 지원하고자 합니다. 새로운 문법만 익히는 데 그치지 않고, 요청이 Controller와 Service를 거쳐 SQL과 화면으로 이어지는 구조를 이해하기 위해 출판 ERP를 학습 프로젝트로 선택했습니다.

프로젝트에서는 주문과 재고가 함께 바뀌는 과정에 집중했습니다. 여러 품목 중 하나라도 재고가 부족하면 전체 출고를 되돌리고, 같은 주문을 반복 요청해도 중복 출고되지 않도록 구성했습니다. 단순히 화면이 동작하는 것과 데이터가 일관되게 저장되는 것은 다르다는 점을 실제 DB 테스트와 버그 재현 사례로 확인했습니다.

현재는 구현된 코드와 테스트를 작은 기능 단위로 복습하면서 Java/Spring의 트랜잭션과 인증 흐름을 학습하고 있습니다. 기존 유지보수 경험을 바탕으로 팀의 코드와 업무 규칙을 익히고, 변경 이유와 검증 결과를 설명할 수 있는 개발자로 성장하고자 합니다.

## 제출 전에 확인할 내용

- 경력 기간·회사명·업무·본인 역할과 지원서의 신입/주니어 분류는 실제 이력과 공고를 보고 결정한다. 기존 유지보수 경력을 지우고 경력이 전혀 없다고 적지 않는다.
- AI 개발 보조를 사용한 프로젝트다. 면접에서 질문받으면 도구 사용 범위와 직접 수정·이해한 범위를 사실대로 설명한다. 전체 코드를 혼자 처음부터 작성했다거나 이해를 마쳤다고 과장하지 않는다.
- 기능 설명은 출고→재고→원장 흐름부터 연습한다. 이해하지 못한 구현 세부사항은 추가 학습하고 확인한다.
- 93개는 테스트 개수이며 사용자 수·운영 트래픽·장애 감소 수치가 아니다. 실제 운영 실적이나 성능 보장으로 표현하지 않는다.
- 배포 전에는 운영 중·무중단·실서비스 경험으로 표현하지 않는다. 배포가 끝나면 합성 데이터 시연 서비스라는 범위를 밝힌다.
- 채용 공고가 정해지면 해당 공고의 업무·필수 기술과 실제 경험을 연결해 지원 동기를 수정한다. 현재 초안을 그대로 모든 회사에 제출하지 않는다.
