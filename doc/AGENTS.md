# Codex 작업 규칙

## 작업 시작

1. 이 문서와 `PROJECT.md`, `TODO.md`, `DECISIONS.md`를 읽는다. 경로는 저장소 루트의 `doc/` 기준이다.
2. 실제 파일 구조와 Git 상태를 확인하고, 사용자 변경 사항을 보존한다.
3. 요청 범위와 관련된 코드·설정·문서를 확인한다. 문서와 실제 구현이 다르면 차이를 확인하고 함께 정정한다.

## 구현 원칙

- 사용자의 최신 지시를 우선한다. 불확실한 요구사항을 확정된 사실처럼 기록하지 않는다.
- 요청에 필요한 범위로 변경한다. 기술 스택과 업무 범위는 요구사항을 확인한 뒤 결정한다.
- 비밀키, 인증 토큰, 실제 고객 정보와 운영 데이터를 저장소에 넣지 않는다.
- 기존 파일이나 이력을 임의로 삭제하거나 덮어쓰지 않는다. 강제 푸시와 파괴적인 Git 명령을 사용하지 않는다.
- 실행 가능한 코드가 생기면 변경 범위에 적합한 검사·테스트를 실행한다. 실행하지 못한 검사는 이유를 기록한다.
- 문서는 한국어로 작성한다. 명령어와 경로는 실제 환경과 일치하도록 유지한다.

## 문서 관리

- `PROJECT.md`: 목적, 구현 상태, 실제 구조와 기술 스택을 관리한다.
- `TODO.md`: 할 일과 완료 상태를 관리한다. 미완료 작업을 완료로 표시하지 않는다.
- `CHANGELOG.md`: 완료한 변경과 검증 결과를 날짜별로 기록한다.
- `DECISIONS.md`: 중요한 설계 결정, 이유, 영향과 재검토 조건을 기록한다.
- `README.md`: 설치·실행·검증 절차를 관리한다. 아직 없는 실행 명령을 만들지 않는다.
- 작업이 끝나면 반드시 `TODO.md`와 `CHANGELOG.md`를 갱신한다. 구조·설계·실행 방법이 바뀌면 해당 문서도 갱신한다.
- 날짜는 한국 시간(Asia/Seoul) 기준 `YYYY-MM-DD`를 사용한다.

## 작업 완료 보고

변경 내용, 검증 결과, 남은 작업을 간결하게 보고한다. GitHub 연결이나 푸시 성공 여부는 실제 명령 결과로 확인한다.
