# 무료 우선 시연 호스팅 후보

확인일: 2026-10-21. 아직 서버가 없으며 계정 생성·카드 등록·결제·VM 생성·실제 배포는 수행하지 않았다. 아래는 후보와 후속 절차다.

## 우선 후보: Oracle Cloud Always Free ARM VM

현재 공식 문서는 A1.Flex 무료 한도를 월 1,500 OCPU 시간/9,000 GB 시간, Always Free 계정 총 2 OCPU·12GB 메모리로 안내한다. 예전 글의 4 OCPU·24GB를 그대로 따라 설정하지 않는다. 실제 계정의 한도·기존 사용량과 생성 화면의 무료 표시를 다시 확인해야 한다.

이 프로젝트에는 Ubuntu ARM VM 한 대에 Java 21 실행 WAR와 MariaDB를 두는 구성이 후보가 된다. Oracle의 별도 DB 상품으로 바꾸는 것이 아니라 VM 안에서 MariaDB를 실행한다. 지금 앱 힙 768MB와 DB 버퍼 128MB를 유지하려면 최소 2GB 이상, 시연 여유를 위해 4GB 정도의 VM 메모리부터 검토한다. 이는 설계 제안이며 원격 부하 검증 결과가 아니다.

가입 시 카드 신원 확인이 필요하다. 지역의 무료 자원이 부족하면 즉시 생성하지 못할 수 있고, 유휴 인스턴스는 회수될 수 있다. 취업 심사자가 언제나 접속할 수 있다고 보장하지 않으며 시연 화면·대본과 저장소를 함께 준비한다. 무료 체험 크레딧으로만 유지되는 유료 VM과 Always Free를 구분한다. 유료 계정 전환을 기본 해결책으로 진행하지 않는다.

근거: [Always Free 공식 한도·용량·회수 정책](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm), [가입·카드 확인 FAQ](https://www.oracle.com/cloud/free/faq/).

## Render 무료 구성과 비교

Render 무료 Web Service는 512MB이며 15분 유휴 시 중지된다. 무료 서비스의 파일시스템은 재시작/재배포 시 보존되지 않고 영구 디스크를 붙일 수 없다. 제공되는 무료 관계형 DB는 PostgreSQL이며 30일 뒤 만료된다. 현재 WAR+MariaDB를 보존하는 단일 무료 시연 구성으로 바로 옮기기에는 맞지 않는다고 판단한다. 별도 외부 MariaDB나 유료 디스크가 필요해질 수 있어 우선 후보로 정하지 않았다.

근거: [무료 서비스 제한](https://render.com/docs/free), [RAM/CPU 계획](https://render.com/docs/compute-plans).

## 서버가 준비된 뒤 할 작업

1. 사용자가 후보를 선택하고 본인 계정에서 무료 한도·지역·약관·카드 확인을 진행한다. 비밀번호·카드 정보·SSH 개인키를 채팅이나 저장소에 넣지 않는다.
2. Ubuntu 버전/CPU/메모리, SSH 접속 별칭, 도메인 또는 HTTPS용 호스트명을 정한다. VM 생성·네트워크 변경은 실제 계정 상태와 비용을 확인한 뒤 수행한다.
3. 배포 파일을 준비한다. 일반 사용자 실행, Java21 WAR, DB 내부 전용, HTTPS 역방향 프록시, prod 보안 설정, 재시작·로그·백업을 구성한다. 현재 loopback HTTP용 Compose를 그대로 인터넷에 공개하지 않는다.
4. 빈 서버에서 설치/마이그레이션·강한 관리자 암호·조회용 시연 계정을 준비한다. 채용 담당자에게 관리자 암호를 공개하지 않는다. 공개 쓰기 계정 제공은 별도 범위로 정한다.
5. 외부 HTTPS 로그인·메뉴·읽기 권한·쿠키·세션·업무 시연·백업 복원을 검증한다. 서비스 URL이 생기기 전 지원서에 운영 중이라고 쓰지 않는다.
6. README의 시연 URL·배포 구조·실제 검증일을 갱신한다.

Docker는 필수가 아니다. 현재 Dockerfile/Compose는 로컬 시연용 준비 파일이며 서버 배포 방식은 계정/서버 선택 후 정한다. 계정과 서버가 없는 상태에서 배포 성공을 보고하지 않는다.
